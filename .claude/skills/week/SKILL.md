# /week <7 тем> — неделя роликов

> **Изменено владельцем 12.11.2026:** выпуски недели делаются **по очереди в этой же сессии** (скил `episode` подряд), новые сессии через `create_session` не создавать. Разделы ниже про отдельные сессии — устарели; план, матрица разнообразия, приёмка и слияние в main — в силе. После каждого выпуска: коммит, push, слияние в main, `STATUS.md`, ролик и обложка владельцу.

**Почему так, а не всё в одном чате.** Один выпуск съедает ≈ 600 тыс. токенов контекста (019 Железногорск: 609K из 1M). Два-три выпуска в одном чате → автосжатие контекста → агент теряет детали правил и начинает экономить на рисовании — так 011–018 стали беднее эталона. Поэтому **один выпуск = одна свежая сессия**, а этот чат — только координатор: план, запуск, проверка, слияние, отправка роликов. Сам координатор миры не рисует.

## 1. План (в этом чате, ≈ 10 мин)
1. Прочитать: `CLAUDE.md`, `STATUS.md`, `docs/cities.md` (что уже было: хуки, структуры, финальные фразы), последний раздел «Выводы» в `docs/stats.md`, «Меню вариаций» в `docs/episode-formula.md`.
2. Номера: следующие свободные после максимального в `episodes/` (005–009 зарезервированы под ветки Кишинёв/Алматы/Рим/Берлин/Владивосток — не брать).
3. По каждой теме 1–2 поиска (WebSearch standard, параллельно): есть ли сильный проверяемый хук. Тема только про текущую войну/политику (как 015 Малая Токмачка) — не делать, предложить замену.
4. **Матрица разнообразия** (правило «не конвейер»): 7 разных типов хука (невозможная картинка · шок-цифра + вопрос · вопрос-загадка · «вы ошибались» · спор/гордость · шок-находка · обратный отсчёт) и 7 разных структур (хронология · обратная хронология · один предмет · одно место · 3 тайны · рассекреченное досье · спор двух эпох), своя палитра и «семейство» переходов у каждого, ни одна пара подряд не совпадает и не повторяет 3 последних выпуска из `docs/cities.md`. Сюда же — что зритель «и так знает» (миф для опровержения) и повод переслать.
5. Записать `docs/week/<ГГГГ-ММ-ДД>.md`: таблица `№ | тема | хук (тип + черновая фраза) | структура | палитра | переходы | миф | почему перешлют`. Коммит в ветку координатора.
6. Владельцу — план одной таблицей (коротко). Если владелец написал «делай сразу» / «без согласования» — не ждать, запускать.

## 2. Запуск — по одному, каждый в новой сессии
Для текущего выпуска (`mcp__claude-code-remote__create_session`, загрузить через ToolSearch):
- `source_url` — `https://github.com/darkuseone/tom-tur`, `source_revision: main` (свежий main — уже со всеми костюмами, звуками и правилами прошлых выпусков недели);
- `title` — `ТОМ-ТУР <NNN> <Город>`; `environment_id` и модель — не задавать (наследуются: там ключ ElevenLabs);
- `prompt` — шаблон ниже (подставить строку из плана).

```
/episode <NNN-slug> <Тема>
Бриф недели (docs/week/<дата>.md, строка <NNN>): хук — <тип>: «<черновая фраза>»; структура — <…>; палитра — <…>; переходы — <семейство>; миф — <…>; почему перешлют — <…>.
Владелец утвердил неделю: сценарий не ждёт «ок», делай сразу до готового ролика. Один выпуск в этой сессии — ничего больше.
Ветка episode-<NNN>-<slug> от свежего main. Ворота качества из /episode обязательны (detail.py и soundcheck.py до рендера, finalcheck.sh после). Готовые выпуски не трогать.
В конце: коммит, push, PR в main, и send_message в сессию-координатор <ID этой сессии>: «ГОТОВО <NNN> | PR #… | длина … | LUFS … | слабые места: …».
Если тема небезопасна или нет проверяемых фактов: send_message «СТОП <NNN>: причина» и остановиться.
```

**Последовательно, а не параллельно** (по умолчанию): параллельные сессии конфликтуют в общих файлах (`engine/tom.js`, `assets/sfx/CATALOG.md`, `docs/*`), бьются в лимит параллельных запросов ElevenLabs и не видят костюмы/звуки друг друга. Если владелец просит быстрее — максимум 2 параллельные дорожки, конфликты общих файлов разрешает координатор при слиянии (оставлять обе стороны; `node -e "new Function(require('fs').readFileSync('engine/tom.js','utf8'))"` после слияния).

После запуска — закончить ход: сообщение от дочерней сессии разбудит (выпуск ≈ 20 мин по замеру владельца; страховочные проверки не ставить — лишние токены).

## 3. Приёмка каждого выпуска (по сообщению «ГОТОВО»)
1. `git fetch origin main episode-<NNN>-<slug>`; посмотреть `docs/sources/<эп>.md` (факты с источниками), `python3 tools/detail.py <эп>`, `python3 tools/soundcheck.py <эп>` — всё ok.
2. **Влить в main** (владелец разрешил вливать готовые выпуски недели): `git checkout main && git pull && git merge --no-ff origin/episode-<NNN>-<slug> -m "Слияние: <NNN> <Город>"`; проверить синтаксис `engine/tom.js` (команда выше); `git push origin main`. PR закроется как слитый.
3. `tools/chatcopy.sh <эп>` (копия < 29,4 МиБ из `final.mp4`) → SendUserFile `build/<эп>/chat.mp4` + `episodes/<эп>/cover.png` (status proactive) + тексты выкладки из `episodes/<эп>/publish.md` колонкой (TikTok, потом YouTube) + 1–2 строки: длина, слабые места из сообщения.
4. Запустить следующий выпуск (раздел 2) от обновлённого main.
5. «СТОП» или сессия упала (`get_session` → status_bucket `failed`, или страховка нашла, что она стоит > 2 ч без событий): прочитать хвост через `list_events`, перезапустить тот же выпуск новой сессией (с пометкой, где остановилась прошлая) или пропустить тему и сказать владельцу.

## 4. Конец недели
`STATUS.md` (7 строк в «Готово»), `docs/cities.md` (строки выпусков уже внесли дочерние — проверить), `docs/week/<дата>.md` — колонка «итог» (длина, слабые места). Владельцу — сводка одной таблицей + расход: ≈ 450–800 кредитов ElevenLabs на выпуск (голос + новые звуки), выпуск ≈ 20 мин; 3–4 выпуска на 5-часовой лимит подписки (замер владельца).

## Чего не делать
- Не делать два выпуска в одной сессии и не рисовать миры в чате-координаторе.
- Не запускать субагентов внутри выпуска для сцен (CLAUDE.md §7а) — свежая сессия и так даёт полный контекст.
- Не вливать в main выпуск, у которого не прошли detail.py / soundcheck.py / finalcheck.sh.
